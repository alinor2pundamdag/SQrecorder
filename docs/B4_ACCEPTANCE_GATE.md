# B4 — Journal, Vault, and durable recovery acceptance gate

Status: **BLOCKED / NOT ACCEPTED**. Rust foundation is verified; a green Rust gate is not full B4.

## Implemented in this branch — exact-head Rust CI verified
- Vault DEK is now guarded by `Zeroizing` so early errors do not bypass explicit clearing.
- Durable promotion returns a distinct `JournalCommitPending` state when file+directory durability succeeded but journal commit failed; callers must reconcile rather than report success.
- CI toolchain pinned to Rust 1.85.1; verification runs are no longer cancelled by same-branch concurrency.
- Cargo.lock is generated by pinned Rust 1.85.1 CI and now committed. CI requires the tracked lock and uses `--locked` without re-resolving dependencies.
- `core/vault-core`: AES-256-GCM encrypted envelope, random per-file DEK and nonce, AAD authentication, wrapped-DEK interface, zeroization, tamper tests.
- `core/durable-store`: staged write + file sync, staged validation, atomic rename, parent sync, journal callback after promotion, non-destructive recovery inspection, and journal/filesystem reconciliation actions.
- CI compiles/tests all workspace crates with `--locked` and checks formatting. Run #33 passed at exact PR head SHA `29856c0c03019778c030d42824b42b72493bae7b`: strict formatting, committed-lock validation, `cargo check --workspace --locked`, and `cargo test --workspace --all-targets --locked`. Vault regression coverage includes wrapped-key tampering, AAD mismatch, empty/binary payloads, and unsupported envelope version.

## Remaining blockers
- **Plan gap surfaced:** this repository branch contains only the Rust workspace and no Android/KMP Gradle module or Android source set. A real Android Keystore adapter cannot be added safely into a nonexistent platform module. The Rust contract remains an interface; auth-bound unwrap, key invalidation/rotation/recovery, and device tests are not implemented.
- Roadmap and RTM are now recorded in `docs/SQRECORDER_IMPLEMENTATION_ROADMAP.md`; B4-P Android/KMP platform integration and B4-A final acceptance are explicitly scheduled there without changing locked capture/splash/Vault architecture.
- Test XOR key wrapper is test-only and is NOT production key custody.
- Fault injection now covers partial staging write, file-sync failure, rename failure, and parent-directory sync failure; verifies old-final preservation or recovery-visible promotion. Journal callback failure has an explicit pending-reconciliation error. Real-device ENOSPC/crash-cut testing and full production journal/session reconciliation remain.
- Rust toolchain and dependency graph are pinned in CI via rust-toolchain version + committed Cargo.lock; strict exact-head CI is green for the Rust workspace at the exact PR head SHA above.
- Journal canonical JSON enforcement and full journal/session/database reconciliation remain pending.
- No full B4 acceptance or Android platform evidence yet.

B4 remains blocked until security review, comprehensive fault tests, exact-head strict locked CI, complete journal/session integration, and Android Keystore/auth/device evidence pass at exact HEAD. Do not start dependent B5 capture integration on assumption of acceptance.

## Plan integrity / architecture guard
The Keystore adapter is a missing implementation layer, not permission to change the approved Vault design. Keep auth-bound Android Keystore custody, per-file random AES-256 DEK, AES-GCM, offline-first behavior, and locked Quick Capture semantics. Any deviation requires a separate blueprint decision and user approval.
